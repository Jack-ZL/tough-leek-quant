# 用通达信公式写因子

本文面向**使用者**：怎么在因子编辑器里用通达信公式写选股/打分因子，哪些函数能用、哪些不能、报错怎么读。

技术口径（翻译层设计、错误码定义、暖机推断、布尔三值语义）见 [factor-system-design.md §3.6](./factor-system-design.md#36-多语言公式入口dsl--tdx--python现状已可用)。

---

## 1. 三档语言怎么选

因子编辑器左上角有三档切换：**DSL 公式 / 通达信 / Python**。三档写出来的因子**完全等价**——保存后走同一条物化、检验、回测、策略评分链路，下游分不清也不关心你是用哪档写的。

| 档位 | 适合谁 | 写法 |
| :--- | :--- | :--- |
| **DSL 公式** | 想要最全的算子（含横截面 `rank`/`zscore`/`winsorize`） | `rank(-ts_sum(change_pct, 5))` |
| **通达信** | 手上已有通达信/同花顺公式，想直接搬过来 | `DIF:=EMA(CLOSE,12)-EMA(CLOSE,26);`<br>`DEA:=EMA(DIF,9);`<br>`CROSS(DIF,DEA)` |
| **Python** | 需要 DSL 表达不了的 polars 表达式 | `ctx.col("close") / ctx.col("close").rolling_mean(window_size=20).over("symbol") - 1` |

**选通达信档的代价**：只支持 22 个函数（见 §3），且**没有横截面算子**——`rank()` 这类"在今天所有股票里排第几"的能力只有 DSL 档有。

**混写是允许的**：通达信档里未映射的标识符会**原样透传**给 DSL 层，所以你可以写 `ts_mean(C,5)`、`change_pct`，甚至直接引用已注册的因子 id。编辑器在通达信档因此**保留** DSL 算子面板；Python 档则隐藏它（往 Python 代码里插 `ts_mean(` 只会得到语法错误）。

**切换档位会发生什么**：

- 你自己写过的公式**一律保留**，不会被清掉。
- 上一档的校验结果、试算结果、已保存标记**立即作废**——同一段文本在不同档下语义不同（`MA(C,5)` 在 DSL 档是未定义算子），把上一档的"公式有效"留在屏上就是误导。
- 只有当输入框里还是**当前档的示例公式**（或空的）时，才会自动换成新档的示例。

## 2. 通达信档怎么写

### 2.1 语法差异（与你在通达信里的习惯对照）

| 通达信里 | 这里 |
| :--- | :--- |
| `{注释}` 或 `(*注释*)` | 一样支持，翻译时丢弃 |
| `=` 是相等比较 | 一样（**不是**赋值） |
| `<>` 是不等 | 一样 |
| `:=` 中间变量、`:` 输出、`;` 结束语句 | 一样 |
| `AND` / `OR` / `NOT` | 一样（关键字，大小写不敏感） |
| 标识符大小写不敏感、可用中文名 | 一样 |

### 2.2 多语句与中间变量

按语句**顺序**求值，**最后一条语句的值就是因子的值**（与通达信"选股公式取最后一个输出"一致）。后定义覆盖先定义。

```
DIF:=EMA(CLOSE,12)-EMA(CLOSE,26);
DEA:=EMA(DIF,9);
MACD柱:(DIF-DEA)*2;
```

三条限制：

1. **不能前向引用**——`A` 必须在用它的语句**之前**定义（报 E309）。
2. **不能自引用**——`A:=A+1` 这种递推写法无法翻译成单个表达式，明确拒绝而不是猜你的意思（报 E309）。
3. **最后一条不能是 `:=`**——全是中间变量就没有输出值，通达信里这样的公式也画不出线（报 E310）。

### 2.3 列名

`C`/`CLOSE`、`O`/`OPEN`、`H`/`HIGH`、`L`/`LOW`、`V`/`VOL`/`VOLUME`、`AMOUNT` 都认，映射到项目的标准列。

### 2.4 规模上限

| 项 | 上限 | 超限报 |
| :--- | :--- | :--- |
| 公式原文 | 4000 字符 | E302 |
| 词法记号 | 300 个 | E302 |
| 中间变量展开后 | 600 个节点 / 嵌套 12 层 | E302 |
| 窗口 n | 2 ~ 512 | E004 |

> 展开后规模这一条容易踩：**反复引用同一个中间变量会让公式按引用次数相乘膨胀**。`A:=...; B:=A+A; C:=B*B;` 到 `C` 时已经是 4 份 `A` 的展开。六个内置模板实测展开后最大 44 个节点（KDJ 的 J 值），其余都 ≤31，离 600 很远——这条只拦病态写法。

## 3. 函数兼容表（53 条）

编辑器里通达信档下方有「函数兼容表」面板，**带筛选框**，数据实时来自后端（`GET /api/factors/tdx/meta`），本文只是同一张表的快照。输入关键词时全部分区会自动展开，否则命中项会被折叠藏起来。

### 3.1 直接支持（17）

| 通达信 | 翻译成 | 说明 |
| :--- | :--- | :--- |
| `MA(X,N)` | `ts_mean` | 简单移动平均 |
| `EMA(X,N)` | `ts_ema` | α = 2/(N+1) 的指数平滑 |
| `SMA(X,N,M)` | `ts_sma` | ⚠️ **不是**简单移动平均，是 α = M/N 的**递归指数平滑**；要求 `1 ≤ M ≤ N` 且 M 为整数 |
| `REF(X,N)` | `ts_delay` | N 期前的值 |
| `HHV(X,N)` / `LLV(X,N)` | `ts_max` / `ts_min` | 滚动最高/最低 |
| `SUM(X,N)` | `ts_sum` | 滚动求和 |
| `STD(X,N)` | `ts_std` | 滚动**样本**标准差 |
| `IF(C,A,B)` / `IFF(C,A,B)` | `if_else` | 三元 |
| `BARSLAST(C)` | `ts_barslast` | 条件**上次**成立到现在的 bar 数 |
| `BARSSINCE(C)` | `ts_barssince` | 条件**首次**成立到现在的 bar 数 |
| `ABS` / `LOG` / `SQRT` | `abs` / `log` / `sqrt` | |
| `MAX(A,B)` / `MIN(A,B)` | `max` / `min` | 横向取大/取小（**不是**滚动极值） |

### 3.2 宏展开（5）

这几个不是原生算子，翻译期展开成等价表达式：

| 通达信 | 展开为 |
| :--- | :--- |
| `CROSS(A,B)` | `A > B and REF(A,1) <= REF(B,1)` |
| `LONGCROSS(A,B,N)` | `CROSS(A,B) and REF(EVERY(A<B,N),1)` |
| `COUNT(C,N)` | `SUM(IF(C,1,0),N)` |
| `EVERY(C,N)` | `COUNT(C,N) == N` |
| `EXIST(C,N)` | `COUNT(C,N) > 0` |

> `CROSS` 判"前一根"用 `<=` 而不是 `<`。均线金叉前一刻两条线常常**正好相等**，用 `<` 会系统性漏掉这一天。这是刻意口径，已加测试锁死。

### 3.3 不支持（31）——按原因分四类

**未来函数（7，报 E304，硬禁止）**：`ZIG` `FLATZIG` `PEAK` `PEAKBARS` `TROUGH` `TROUGHBARS` `BACKSET`

> 这些函数的拐点/极值会**随新行情重绘**——今天算出来的"上周低点"，下周可能就不是了。放进回测等于用未来数据，收益曲线会好看得离谱但无法复现。这是本项目最不肯让步的一条。

**缺数据（11，报 E305）**：`FINANCE` `CAPITAL` `COST` `WINNER` `DYNAINFO` `INDEXO` `INDEXH` `INDEXL` `INDEXC` `INDEXV` `INDEXA`

> 需要财务快照、流通股本、筹码分布、盘中实时、大盘指数序列，当前因子面板里没有这些列。`DYNAINFO` 还有一层原因：因子只在**收盘 bar** 上计算。

**绘图类（11，报 E305）**：`DRAWTEXT` `DRAWTEXT_FIX` `DRAWNUMBER` `DRAWICON` `DRAWLINE` `DRAWBAND` `DRAWKLINE` `DRAWGB` `STICKLINE` `PARTLINE` `POLYLINE`

> 因子是一个数值序列，画图在计算里没有意义。

**无法向量化（2，报 E305）**：`AVEDEV` `DMA`

> `AVEDEV` 是真·逐窗平均绝对偏差，`DMA` 的 α 是**序列**而非常量。两者在 polars 里只能退化成逐行 Python 回调，全市场 × 全历史会慢到不可用。

## 4. 翻译预览怎么读

通达信档点「校验」后，除了通过/失败，还会显示**后端实际参与计算的等价 DSL 文本**。

```
DIF:=EMA(CLOSE,12)-EMA(CLOSE,26); DEA:=EMA(DIF,9); CROSS(DIF,DEA)
```
↓
```
((ts_ema(close, 12) - ts_ema(close, 26)) > (ts_ema(ts_ema(close, 12) - ts_ema(close, 26), 9))
 and ts_delay(ts_ema(close, 12) - ts_ema(close, 26), 1)
     <= ts_delay(ts_ema(ts_ema(close, 12) - ts_ema(close, 26), 9), 1))
```

（实际显示为一行，这里为了看清折行了。）

它的用途是**把黑盒变白盒**：你能确认 `SMA` 真的变成了指数平滑而不是简单均线、`CROSS` 真的用了 `<=`、中间变量真的被内联展开了。

三个要点：

1. **报错位置指回你写的通达信原文**，不是这段生成文本。存盘保存的也是你的原文，翻译每次现算。
2. **编译失败时照样给预览**——那正是排错最需要的东西。例如 `MA(C,0)` 会显示 `ts_mean(close, 0)` + E004，你一眼能看出"0"是被**原样带过去**的，不会怀疑翻译器偷偷改了你的参数。
3. **翻译本身就失败时预览为空**（比如用了 `ZIG`），此时看错误码即可。

## 5. 内置模板（6 个）

通达信档的「通达信公式模板」面板按类别分组，点一下就把公式填进输入框（会替换当前内容）。角标区分两种产出：

- **数值**：连续值，可用来打分/排名（如 MACD 柱、J 值、RSI、BOLL 位置）
- **信号**：布尔值，可直接当选股条件（如 MACD 金叉、均线多头排列）

| 模板 | 类别 | 产出 |
| :--- | :--- | :--- |
| MACD 柱 | 趋势 | 数值 |
| MACD 金叉 | 趋势 | 信号 |
| KDJ 的 J 值 | 摆动 | 数值 |
| RSI(6) | 摆动 | 数值 |
| BOLL 带内位置 | 通道 | 数值 |
| 均线多头排列 | 均线 | 信号 |

## 6. 空值与暖机：为什么前 N 天没信号

这是最容易误判成 bug 的一件事，单独说明。

**数据不够时返回空值（null），不是 0，也不是报错。** 例如 `MA(C,20)` 在前 19 根 bar 上是 null；`RSI(6)` 在横盘无波动时分母为 0，结果也是 null 而非报错。

空值往下游传播，最终在选股条件里被当成**"不成立"**——即**不出信号**。这与通达信"数据不够就不画线"的行为一致，是保守正确的：宁可漏一天，也不要凭空造一个假信号。

**暖机长度会自动推算**，你不用手填：

| 算子类型 | 暖机 |
| :--- | :--- |
| 普通滚动（`MA`/`HHV`/`SUM`/…） | 窗口 n + 1 |
| 指数平滑（`EMA`/`SMA`） | **4n**（指数衰减残差降到 4e-4 以下） |
| `BARSLAST`/`BARSSINCE` | **至少 250 根**（"上次成立"可能在任意久之前，记忆无上界） |

所以一个用了 `BARSLAST` 的因子需要约一年历史才开始出有效值。**数据不足不会报错**——那段就是空值，检验样本相应减少；区间太短时 IC 结果不可用，把区间拉长即可。

**布尔逻辑是三值的**（真 / 假 / 未知）：`假 AND 未知 = 假`、`真 AND 未知 = 未知`。`LONGCROSS` 在预热期用这套三值逻辑——"上穿没发生"直接判假，不必等前置条件算出来。

## 7. 两条已知限制

刻意口径，不是待修的 bug，已加测试锁住：

1. **单字母 `C` `H` `L` `O` `V` 不能当中间变量名。** 它们是列别名。通达信里写 `L:=LLV(LOW,20);` 是常见写法，这里会报 E309（保留名），换个名字即可（如 `LOW20:=...`）。同理，任何函数名也不能当变量名。
2. **未被引用的中间变量不做语义校验。** `BAD:=ZIG(C,3); MA(C,5)` 能编译通过——因为 `BAD` 没被引用，翻译期直接丢弃了它。一旦引用（`BAD+MA(C,5)`）就会报 E304。所以"校验通过"**不等于**"公式里没有未来函数"，只等于"最终输出的那条表达式里没有"。

## 8. 报错速查

### 通达信翻译层（E3xx）

| 码 | 含义 | 怎么办 |
| :--- | :--- | :--- |
| E301 | 公式为空 | 写点东西 |
| E302 | 规模超限 | 见 §2.4；多半是中间变量被反复引用导致膨胀 |
| E303 | 语法错误 | 检查括号、分号、`:=` 与 `:` 有没有写反 |
| E304 | **未来函数** | 换掉 `ZIG`/`PEAK`/`TROUGH` 这类会重绘的函数，没有变通办法 |
| E305 | 函数不支持 | 查 §3.3 看属于哪一类；缺数据类可以等数据层扩展 |
| E307 | 不支持字符串常量 | 因子只能是数值序列 |
| E308 | 参数个数不符 | 报错里会写期望几个、实际几个 |
| E309 | 中间变量非法 | 前向引用 / 保留名 / 自引用，见 §2.2 与 §7 |
| E310 | 公式没有输出值 | 末尾补一条输出（`名字:表达式;` 或直接写一个表达式） |

### 翻译成功后仍可能报的 DSL 层错误（E0xx）

| 码 | 含义 |
| :--- | :--- |
| E001 | 未知标识符（列名或因子 id 拼错） |
| E002 | 未知函数 |
| E003 | 参数数量/类型不符 |
| E004 | 窗口越界（n ∉ [2,512]，或 `SMA` 的 M 不满足 `1 ≤ M ≤ N`） |
| E005 | 负偏移（等价于未来函数） |
| E008 | 静态除零 |
| E013 | 依赖列不可用（面板缺列，试算时报） |
| E016 | 常量表达式（整条公式没有任何数据依赖，拒绝保存） |

完整目录见 [factor-system-design.md §3.4](./factor-system-design.md#34-形式文法ebnf与错误码目录设计)。注意该目录里的 **E012（循环引用）与 E015（预热不足）是设计保留码，当前代码不会产生**——因子依赖成环在注册表层就被挡住，预热不足表现为空值而非报错（见 §6）。

## 9. 给二次开发者：布尔因子的 `nan` 地雷

因子列统一是 **Float64**，布尔因子即 `1.0 / 0.0 / nan`。而 **numpy 的 `nan.astype(bool)` 是 `True`**——直接读原始因子列做掩码，预热期的空洞会被读成一堆**假信号**。

生产链路本身安全（`app/strategy/custom_signals.py`、`app/backtest/matrix.py::_scatter_bool_series` 都在 polars 表达式层先 `fill_null(False)` 再 cast）。但**新写的代码和测试**必须自己注意：

- polars 侧：`expr.fill_null(False).cast(pl.Boolean)`
- numpy 侧：显式三值转换，参考 `backend/tests/test_factor_tdx.py::_bool_or_none`

口径详见 [factor-system-design.md §3.6](./factor-system-design.md#36-多语言公式入口dsl--tdx--python现状已可用)。
